────────────────────────────────────────────────────────────────────────────────
۱. این پروژه چیست و چه مشکلی حل می‌کند؟
────────────────────────────────────────────────────────────────────────────────

وقتی فارسی/عربی (راست‌به‌چپ) و انگلیسی (چپ‌به‌راست) در یک خط یا پاراگراف
ترکیب می‌شوند، موتور BiDi مرورگر یا ویرایشگر گاهی ترتیب کلمات، پرانتزها،
URLها و مسیرها را اشتباه نشان می‌دهد.

مثال رایج:
  ورودی:  سلام hello دنیا
  خروجی: سلام ‎hello‎ دنیا   (با کاراکترهای نامرئی LRM دور «hello»)

این پروژه یک «موتور متن» مشترک دارد و آن را در دو محصول استفاده می‌کند:
  • افزونه VS Code / Cursor  — اصلاح دستی یا نیمه‌خودکار متن در ادیتور
  • افزونه Chrome (MV3)     — اصلاح خودکار در صفحات وب (به‌ویژه چت‌های AI)

لایسنس: MIT
زبان پیاده‌سازی: TypeScript
بیلد: pnpm workspace، esbuild (افزونه‌ها)، tsc (core)

─── packages/shared ───
نقش: قرارداد داده بین core و مصرف‌کننده‌ها.
فایل اصلی: src/types.ts

تعریف می‌کند:
  • Direction — RTL, LTR, NUMBER, PUNCTUATION, WHITESPACE, OTHER
  • Token — { value, dir, kind? }  kind می‌تواند url | email | path | code باشد
  • ParagraphDirection — rtl | ltr | neutral
  • FixMixedTextOptions — mode: legacy | enhanced
  • FormatUiTextOptions — برای پیام‌های UI

چرا جداست؟ تا core و افزونه‌ها بدون وابستگی چرخه‌ای از یک API تایپ‌شده
استفاده کنند. scale: کم‌حجم، تغییرات API اینجا نسخه‌گذاری می‌شود.


─── packages/core ───
نقش: کتابخانه pure TypeScript — بدون DOM، بدون VS Code، بدون Chrome.
ورودی/خروجی: رشته متن → رشته اصلاح‌شده.

جریان fixMixedText() (فایل index.ts + bidiFixer.ts):

  1) normalizeText()      — یکسان‌سازی فاصله و خط جدید
  2) stripBidiMarkers()   — در حالت enhanced، مارکرهای قبلی حذف می‌شوند
                            (جلوگیری از انباشت LRM/RLM)
  3) tokenizeNormalized() — شکستن متن به توکن‌ها با جهت هر بخش
  4) detectParagraphDirection() — تشخیص جهت غالب پاراگراف
  5) applyBidiMarkers()   — درج مارکر Unicode مناسب
  6) join توکن‌ها → خروجی نهایی

ماژول‌های core:

  languageDetector.ts
    • تشخیص کلاس هر کاراکتر (فارسی، عربی، لاتین، عدد، علامت)
    • پایهٔ tokenize

  segments.ts
    • iterateGraphemes — کار با grapheme cluster (ایموجی و حروف ترکیبی)

  tokenizer.ts
    • tokenizeText / tokenizeNormalized
    • ادغام کاراکترهای هم‌جهت در یک توکن
    • شناسایی spanهای اتمی LTR (URL، ایمیل، مسیر، کد backtick)

  runs.ts
    • findAtomicLtrSpans — regex برای https://، email، path ویندوز/یونیکس، `code`
    • این بخش‌ها در enhanced با isolate (LRI/RLI/PDI) wrap می‌شوند

  bidiFixer.ts
    • legacy: فقط LRM دور توکن‌های LTR در زمینه RTL
    • enhanced: LRM/RLM + isolate برای URL/path + RLM برای RTL در پاراگراف LTR

  isolates.ts
    • ثابت‌ها: LRM \u200E, RLM \u200F, LRI/RLI/FSI/PDI \u2066-\u2069
    • stripBidiMarkers, wrapLrm, wrapRlm, wrapIsolate, hasBidiMarkers

  detectDirection.ts
    • detectParagraphDirection — rtl / ltr / neutral از روی اکثریت حروف قوی

  formatUiText.ts
    • formatUiText — برای نوتیفیکیشن و UI افزونه VS Code (متن مخلوط readable)

  normalize.ts
    • نرمال‌سازی Unicode و فاصله‌ها

تست: packages/core/src/__tests__/fixMixedText.test.ts (vitest)

محدودیت فعلی core:
  • تمرکز روی فارسی/عربی + لاتین؛ زبان‌های RTL دیگر تا حدی با همان range کار می‌کنند
  • یک پاراگراف در هر فراخوانی؛ متن چندخطی هر خط جدا پردازش نمی‌شود مگر consumer این کار را بکند
  • بدون آگاهی از HTML — consumer مسئول DOM است

─── packages/chrome-extension ───
نسخه manifest: 0.3.4
Manifest V3 — content script + service worker + popup

فایل‌های کلیدی:

  manifest.json
    • matches: <all_urls>  — اسکریپت روی همه URL inject می‌شود
    • all_frames: false    — فقط فریم اصلی تب (برای جلوگیری از hang در iframeها)
    • permissions: storage

  background.ts
    • service worker سبک — پیش‌فرض enabled در sync storage
    • پیام GET_ENABLED / SET_ENABLED

  storage.ts
    • rtlTextFixerEnabled
    • rtlTextFixerSiteScope: all | presets
    • includeHosts / excludeHosts (لیست host اضافی یا مستثنی)

  siteScope.ts
    • BUILTIN_PRESET_HOSTS — chatgpt, claude, gemini, grok, perplexity, ...
    • computeEffectiveEnabled — آیا روی این tab کار کند؟

  popup.html / popup.ts / popup.css
    • UI: روشن/خاموش، محدوده سایت، hostهای اضافی/مستثنی

  content.ts  (بزرگ‌ترین فایل — منطق اصلی صفحه)
    جریان کلی وقتی enabled است:

    1) init() — خواندن storage، wire listener
    2) فقط در فریم اصلی (isMainContentFrame): startObservers()
    3) MutationObserver روی document.body + shadow rootهای باز
    4) scanDocument — اسکن پیام‌های chat + wire کردن composerها (با debounce)
    5) onDomMutation — batch شده (~32ms) تا CPU overload نشود

    دو مسیر اصلاح:

    A) Composer (قابل ویرایش)
       • textarea یا contenteditable
       • ensureEditableWired — listenerهای input/blur/paste
       • ProseMirror (ChatGPT, Claude): فقط پاراگراف caret هنگام تایپ؛ blur = همه p
       • tryFixMixedBlockCoalesced — بدون execCommand روی کل بلاک

    B) پیام‌های read-only (پاسخ assistant)
       • messageSurfaces.ts
       • سلکتور بر اساس host: Claude data-testid، ChatGPT data-message-author-role،
         Gemini .message-content، عمومی .ProseMirror غیر contenteditable
       • applyReaderBidiStack — dir=auto, unicode-bidi: plaintext روی p و لیست‌ها
       • fixReadOnlyBlock — fixMixedText روی متن coalesced
       • isStillStreaming — تا پایان stream دست نمی‌زند

  geminiQuill.ts — مسیر جدا برای gemini.google.com
    • Quill editor: فقط CSS + strip مارکرهای اضافی
    • عمداً بدون LRM/RLM در composer (Quill span می‌شکند)
    • maintainGeminiComposer — debounced

  blockFix.ts
    • shouldFixMixedText — فقط وقتی هم فارسی هم انگلیسی باشد
    • fixBlockCoalescedTextNodes — یک text node اصلی + خالی کردن بقیه
    • getCaretOffsetInBlock / setCaretOffsetInBlock — حفظ مکان‌نما

  domDeep.ts
    • querySelectorAllDeepFrom — عبور از shadow DOM باز
    • hookShadowRootsInTree — observer روی ShadowRoot

  esbuild.config.ts
    • content.js به صورت IIFE (Chrome ESM نیست)
    • alias به core/src برای بیلد بدون pre-build core

store/ — آماده Chrome Web Store
  • LISTING.md, privacy-policy.md, UPLOAD_GUIDE.md
  • scripts/pack-store-zip.mjs → store/release/*.zip
  • scripts/generate-icons.mjs — آیکون و اسکرین‌شات


────────────────────────────────────────────────────────────────────────────────
۳. جریان داده (از دید کاربر)
────────────────────────────────────────────────────────────────────────────────

کاربر Chrome:
  Popup ON → storage.sync → content script همان tab را applyEnabled(true)
  → observer + scan → تایپ در ChatGPT → debounce → fixMixedText روی پاراگراف
  → متن با مارکر در DOM (یا فقط CSS در Gemini)

کاربر VS Code:
  انتخاب متن → Ctrl+Alt+R → fixMixedText → replace selection
  یا clipboard fix → paste در چت

هیچ سرور backend، analytics اجباری، یا ارسال متن به cloud در کد پایه نیست —
فقط chrome.storage.sync و تنظیمات محلی.

۵. پتانسیل Scale (فنی و محصول)
────────────────────────────────────────────────────────────────────────────────

─── Scale فنی (تا کجا می‌تواند بزرگ شود بدون بازنویسی کامل) ───

الان (سطح کوچک–متوسط):
  • ~۷۸ فایل سورس، monorepo تمیز
  • core بدون side effect — قابل embed در Node، CLI، WASM، موبایل
  • Chrome: یک content script سنگین روی all_urls — گلوگاه CPU و نگهداری

محدودیت‌های scale فعلی:
  1) content.ts متمرکز — هر سایت خاص (Gemini) شاخه if اضافه می‌شود
  2) MutationObserver روی کل body — حتی با debounce روی صفحات DOM عظیم سنگین است
  3) <all_urls> — Review فروشگاه سخت‌تر؛ کاربران نگران حریم خصوصی
  4) تست end-to-end مرورگر کم است — رگرسیون دستی روی AI chatها

برای scale به ۱۰۰k+ کاربر فعال:
  • manifest matches محدود به preset hosts + chrome.scripting.registerContentScripts
    دینامیک وقتی کاربر «همه سایت‌ها» را انتخاب کرد
  • معماری plugin per-site: adapters/chatgpt.ts, gemini.ts, grok.ts
  • Web Worker برای fixMixedText روی batchهای بزرگ DOM
  • جدا کردن «فقط CSS» vs «مارکر» per adapter
  • telemetry opt-in و crash reporting (Sentry) بدون محتوای متن

برای scale به ۱M+:
  • WASM build از core برای سرعت
  • Safari/Firefox extension (WebExtensions مشترک)
  • API SaaS: POST /fix { text, locale } برای اپ‌های third-party
  • npm package @rtl-text-fixer/core با دانلود هفتگی بالا

─── Scale محصول (بازار) ───

بازار هدف طبیعی:
  • کاربران فارسی/عربی در GitHub, ChatGPT, Claude, ایمیل وب، Notion, Confluence
  • توسعه‌دهندگان Cursor/VS Code
  • تیم‌های پشتیبانی دوزبانه

رقبا / جایگزین:
  • تنظیمات دستی dir=rtl در HTML
  • افزونه‌های عمومی RTL browser
  • مزیت این پروژه: تخصصی برای mixed-script + AI chat DOM

تخمین واقع‌بینانه با تمرکز AI chat:
  • نیش قوی: ۵۰k–۲۰۰k نصب Chrome ممکن با بازاریابی جامعه فارسی/توسعه‌دهنده
  • VS Code marketplace: ۱k–۱۰k نصب اگر publish و README قوی باشد
  • بدون publish/store و SEO: محدود به مخزن GitHub

────────────────────────────────────────────────────────────────────────────────
۸. خلاصه یک پاراگرافی
────────────────────────────────────────────────────────────────────────────────

RTL Text Fixer یک monorepo TypeScript است: core خالص برای درج مارکرهای Unicode
BiDi در متن مخلوط فارسی/عربی/انگلیسی؛ افزونه VS Code برای اصلاح selection و
کلیپ‌بورد و RTL UI اختیاری؛ افزونه Chrome برای اجرای خودکار روی DOM چت‌های AI
با منطق جدا برای composer (ProseMirror/Quill) و پاسخ read-only. scale فنی با
جداسازی adapter و محدود کردن inject قابل رشد به صدها هزار کاربر است؛ scale محصول
در نیش جامعه فارسی‌زبان و توسعه‌دهندگان AI tooling قوی است. خفن‌شدن واقعی با
site adapters تست‌شده، CLI/API، مرورگرهای بیشتر، fix-on-paste، و ادغام عمیق
با Cursor/ChatGPT قبل از ارسال prompt اتفاق می‌افتد.
